# uncvl.xyz: notes for Claude

The website of Uncivilization. Eleventy 3 + Sveltia CMS, deployed on Cloudflare. The README has the full layout and how things work; this file is the short list of things to know before changing anything.

## Where things live

- Code: GitHub `uncvl/uncvl.xyz` (git remote `origin`). The old Codeberg repo (`codeberg` remote) is frozen: never push there.
- Deploys: Cloudflare Workers Builds builds every push to `main` (Worker `uncvl`, build command `npm run build && npm run check`). A deploy shows as the check run "Workers Builds: uncvl" on the commit (`gh api repos/uncvl/uncvl.xyz/commits/<sha>/check-runs`).
- `wrangler.jsonc` exists, so use Wrangler (not the `cf` CLI) for Cloudflare. Its `build.command` is ignored by Workers Builds; the build command lives in the Cloudflare dashboard.
- Media: Cloudflare R2, public at `https://media.uncvl.xyz`. CMS uploads go through `worker/index.js` (`/api/media`), which also does the CMS's GitHub sign-in (`/api/auth`, secret `GITHUB_CLIENT_SECRET`).
- GitHub org page: `profile/README.md` in the `uncvl/.github` repository.

## Working rules

- Push to `main` only when the user says so ("Push to main"). Before pushing, fetch: the team edits content through the CMS, so `main` often has new `content: …` commits; rebase on them, then rebuild and run the check.
- After pushing, wait for the Workers Builds check and confirm the change on the live site.
- Run `npm run build && npm run check` before committing. If the local dev server (`npm run serve`) is running, `npm run clean` can't delete `_site/`; a plain build is enough.
- Content edits from the team arrive as CMS commits (`content: update Event “…”`). Don't rewrite their files beyond what was asked.
- Never invent facts for content (genre links, event details, bios). Use the team's own text or a cited source, and leave a field empty when there is none.
- Every page is bilingual: EN and TR in the same file (`*_en` / `*_tr`). Keep the Turkish UI words short (the menu uses etkinlik, yayın, yazı, hakkında).

## Generated vs hand-written

- `src/_includes/brand/*.svg`, favicons, `.brand/` and `docs/logo-banner.svg` are generated by `scripts/brand.mjs` on every build. Don't edit them by hand.
- `src/_includes/logo-puppet.njk` (the moving home page logo) is hand-written. If the logomark changes, update its shapes too.

## Things that look odd but are on purpose

- List collections (`events`, `releases`, `artists`, `posts`, `calls`) leave out `visibility: unlisted` entries. For lookups (event numbers, linking a lineup name to an artist page) use `allEvents`, `allReleases`, `allArtists`.
- Genres use `visibility: listed | hidden`; hidden genres have no page.
- Event numbers (`evt 0x…`) count all events, so unlisting one doesn't renumber the rest.
- Upcoming vs past is decided at build time. `.github/workflows/rebuild-after-event.yml` pushes an empty commit the day after an event to trigger a rebuild.
